# Verification Loop（検証ループ）

実行者（Executor）と検証者（Verifier）を分離し、成果物の品質を客観的に検証する仕組み。

---

## 基本原則

- **成果物を作ったエージェントは、その成果物の最終判定をしない。**
- 検証は専用のサブエージェントが行う。コード・計画・リサーチは `verifier`、ドキュメントは `doc-verifier`。モデルは各エージェントの frontmatter で固定されている（`governance/routing.md` 参照）。
- 検証者には成果物・受け入れ基準・該当ルーブリック名のみを渡す。実行過程の言い訳や文脈は渡さない（判定を汚染するため）。
- **このファイルが採点ルーブリックと合格閾値の正本。** 検証エージェントは起動時にこのファイルを読んで採点する。ルーブリックを変えるときはここだけを直す。

---

## 発動条件

以下の成果物が完了した時点で検証ループを回す：

| 成果物の種類 | 検証必須 | 備考 |
|------------|---------|------|
| コード変更（medium以上のタスク） | ○ | smallタスクはセルフチェックで可 |
| アーキテクチャ・設計ドキュメント | ○ | |
| リサーチ結果（意思決定に使うもの） | ○ | |
| テンプレート・ガバナンスファイルの変更 | ○ | 全プロジェクトに影響するため |
| state/の更新、軽微な修正 | × | セルフチェックのみ |

---

## 採点ルーブリック

各基準を 0.0〜1.0 で採点し、平均が**合格閾値 0.85** 以上でPASS。

### コード

| 基準 | 内容 |
|------|------|
| 正確性 | 受け入れ基準どおりに動くか。エッジケースは処理されているか |
| セキュリティ | インジェクション経路・認証情報の露出がないか |
| スコープ | タスクに必要な変更のみか。無関係な変更が混入していないか |
| 品質 | 規約準拠、デッドコードなし、テストが挙動を検証しているか |

### リサーチ

| 基準 | 内容 |
|------|------|
| 出典 | 主張に情報源が示されているか。一次情報源を優先しているか |
| 論理整合性 | 結論が根拠から導かれているか |
| 不確実性の明示 | 不明な点・制限が明記されているか |
| 実用性 | 実行可能な推奨につながっているか |

### ドキュメント

| 基準 | 内容 |
|------|------|
| 正確性 | 現在のコード・設計と整合しているか |
| 完全性 | 読者が追加質問なしに行動できるか |
| 精密さ | 曖昧語（「適切に」「基本的に」等）がないか |
| 構造 | 論理的でナビゲートしやすいか |

### 計画

| 基準 | 内容 |
|------|------|
| 検証可能性 | 全ステップに受け入れ基準があるか |
| 依存関係 | 正しくマッピングされているか |
| リスク特定 | 不可逆ステップにフラグが立っているか |
| スコープ | 合意された範囲に収まっているか |

## 検証の委任方法

検証者の役割・姿勢・出力形式は `.claude/agents/verifier.md` と `.claude/agents/doc-verifier.md` にシステムプロンプトとして定義済み。ルーブリックはこのファイルから検証者自身が読む。**Supervisorがプロンプトに転記するのは、対象と基準だけ。**

```
Agent(
  subagent_type: "verifier",     # ドキュメントなら "doc-verifier"
  prompt: """
  ## 成果物
  [ファイルパス、または成果物の内容]

  ## 受け入れ基準
  [タスクで定義された基準]

  ## 適用するルーブリック
  governance/verification.md の「コード」（／「リサーチ」／「ドキュメント」／「計画」）
  """
)
```

**`model` パラメータは指定しない。** `verifier` は sonnet、`doc-verifier` は haiku に固定されている。上書きが必要な例外時のみ指定し、理由を `state/current-task.md` に残す。

渡してはいけないもの：
- Executorの自己評価や「意図としてはこうだった」という説明（判定を汚染する）
- 実装中に起きた事情・言い訳
- 「PASSさせてほしい」といった期待の表明

## リトライとエスカレーション

```
成果物完成
    │
    ▼
検証者が採点
    │
    ├── 平均 ≥ 0.85 → PASS → 次のステップへ
    │
    └── 平均 < 0.85 → 修正指示付きでExecutorに差し戻し
            │
            ▼
        再実行（最大2回）
            │
            └── 2回のリトライ後もFAIL → ESCALATE（人間に報告）
```

**エスカレーション時に報告する内容：**
- 成果物と最終スコア
- 何度も失敗している基準
- 検証者の修正指示と、それでも解決しなかった理由

**リトライで解決しない失敗は `memory/lessons.md` に記録する**（同種の失敗の再発防止のため）。
