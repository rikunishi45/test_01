# Lessons Learned（教訓の記録）

タスクの振り返り（Reflectionフェーズ）で得た教訓を1件ずつ記録する。
**エラーは資産。** ここに記録された教訓が、スキルとガバナンスを改善する唯一の公式な入力源となる。

---

## 記録ルール

1. **いつ書くか：** Reflectionフェーズ、および検証ループでリトライしても解決しなかった失敗の直後。
2. **何を書くか：** 失敗だけでなく、「予想より うまくいったアプローチ」も記録する（成功パターンの検出のため）。
3. **昇格ルール：** 同じ`tag`の教訓が**2回以上**出現したら、該当スキルファイルへの反映案を作成し、**ユーザーの承認を得てから**スキルを更新する。反映済みの教訓には `→ 反映済み（YYYY-MM-DD、対象ファイル）` を追記する。
4. **書かないもの：** 一度きりの環境固有トラブル、コードから自明なこと。

---

## 記録形式

```markdown
### YYYY-MM-DD — [短いタイトル]

- **tag:** [分類タグ。例：verification-fail, scope-creep, research-shallow, routing-mismatch]
- **タスク：** [何をしていたか]
- **事象：** [何が起きたか（失敗／うまくいったこと）]
- **原因：** [なぜそうなったか]
- **教訓：** [次から何を変えるか]
- **対象スキル：** [skills/xxx.md ／ governance/xxx.md ／ なし]
```
